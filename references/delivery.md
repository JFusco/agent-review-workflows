# PR delivery assessment

Require an explicit GitHub PR URL and run directory. This procedure runs in the invoking conversation. It does not add a review stage or change the canonical ledger.

1. Read `status RUN`, `handoff.md`, `state.json`, the terminal accepted artifact, and referenced local check receipts. Require a completed implementation or reported diff run. Match receipts to the saved commands and fingerprint; distinguish failed, missing, and stale checks. Apply the [clean-context prerequisite](cli.md#preparing-review-evidence-for-delivery).
2. Read the exact PR with `gh pr view PR_URL --json url,title,body,state,isDraft,headRefOid,baseRefOid,updatedAt,closingIssuesReferences,mergeable,reviewDecision`. Read its linked issue with `gh issue view ISSUE_URL --json url,title,body,state`. If the linkage or requirements are unclear, report the missing evidence. See the [PR](https://cli.github.com/manual/gh_pr_view) and [issue](https://cli.github.com/manual/gh_issue_view) command references.
3. Read required hosted checks with `gh pr checks PR_URL --required --json name,state,bucket,link`. Inspect each result, including pending results when the CLI exits nonzero. An empty result does not establish that no checks are required. See the [checks command](https://cli.github.com/manual/gh_pr_checks).
4. Run `verify-target RUN --head HEAD_REF_OID --pr-base BASE_REF_OID` using the observed PR commits; follow the [identity command](cli.md#verify-a-terminal-target-for-delivery). Compare issue and PR acceptance criteria with run requirements, reviewed scope, finding decisions, and actual check evidence. A clean finding count alone does not prove coverage.
5. Read the same PR fields again. If head, base, or `updatedAt` changed, return UNKNOWN and identify which evidence needs rereading. Report the observation time.

For a consistent observation, return **BLOCKED** for any known identity mismatch; dirty checkout or changed check context; accepted finding without PASSED independent verification; failed local check; failed, cancelled, or pending required hosted check; draft or closed PR; conflicts; or an unsatisfied required review. Explain unscoped check-context changes separately from scoped-target changes. Known blockers take precedence over missing evidence. Return **UNKNOWN** when required evidence, access, requirement coverage, or check acceptability cannot be established. Do not count skipped checks as executed tests. Return **READY** only when identity and every applicable requirement and gate have supporting evidence. Cite the PR, issue, check URLs, saved fingerprint, and relevant finding IDs. Readiness describes this observation, not future PR state.

Do not edit files, comment, submit a review, rerun checks, call a provider, invoke a companion skill, publish, or merge. Report unavailable authentication as UNKNOWN; do not obtain credentials or change permissions.
